Introduction

Why Converge exists

The old loop ran in your head. A requirement arrived fuzzy, and you held the definition of "done" as private judgment — refined by taste, defended in review, never written down. That loop does not scale to AI engines, because an engine cannot execute a standard it cannot read. The bottleneck was never typing speed; it was that intent lived in a human and had to be re-supervised at every step. The AI-native engineer inverts this: take a fuzzy requirement and lower it through a repeatable descent — each step more precise than the last — until "done" is a machine-checkable condition an engine can satisfy unsupervised.

The main idea — compile intent, don't write the system

Stop writing the system. Compile it. Converge treats building as a compilation pipeline that lowers altitude in fixed stages: intent → structure → plan → tasks → code → loop. Each stage is a transformation with a typed output and a gate that must pass before the next stage runs. You author the high-level intent and the checks; the pipeline emits the system. When no client brief exists, an optional on-ramp — Pass 0 · Capture — compiles the raw idea into the BRD that starts the descent.

The thesis — coordinate authority, never duplicate it

Converge 0.2.0 is deliberately thin. It calls the public binaries of two independently versioned engines and imports nothing: Seamwise is the sole authority for evidence-backed seams, swimlanes, and the reviewed TaskPlan/v1; Task-Spec is the sole authority for task structure, authorization, evals, and acceptance. Converge owns only the cross-engine sequence, the runtime binding, the bounded loop, and the settlement receipts. The method has two phases with one barrier between them: Passes 0–4 are human-led design; Pass 4's owner sign-off is the last human gate before the machine-led build of Passes 5–8.

The authority model — one decision, one owner.

STRICT ENGINE DELEGATION · EXECUTABLE AND JSON BOUNDARIES · DIGEST-BOUND HANDOFFS

Converge coordinates independently versioned engines over executable and JSON boundaries. It never imports or vendors Seamwise or Task-Spec — it calls their public binaries, verifies their contracts, and hashes every boundary artifact before the next authority may act. cvg decompose is a compatibility alias for Seamwise preparation; every cvg tasks verb is an exact delegation to Task-Spec.

THE RULE

Duplicate capability is tolerable. Duplicate authority is not. A Seamwise review does not authorize task dispatch, a Task-Spec materialization receipt does not sign a task, and model narration is never settlement evidence.

BINARY BOUNDARIES — EXPLICIT AND LAZY

Engines resolve through explicit overrides — CVG_TASKSPEC_BIN and CVG_SEAMWISE_BIN — and discovery is lazy: a Seamwise-only prepare or review never requires Task-Spec to be installed. Composition first negotiates SeamwiseCapabilities/v1 (supported major, TaskPlan/v1, lineage contract, materializes_tasks: false, dispatch_authority: false) and separately requires a 3.8.x TaskSpecCLIResult/v1 engine. A missing binary, malformed JSON, or version change mid-command returns COMPOSE=ENGINE_UNAVAILABLE and changes no canonical task state.

Read the BRD like a senior engineer, not a stenographer. Find the real problem underneath the ask, name who actually hurts when it is unsolved, and pin the numbers that define success. Ambiguity left here compounds through every pass downstream — this is the cheapest place in the whole spine to kill it, and the most expensive to leave alone.

The interrogation runs in frontier rounds — facts never enter a round; unanswered questions ride twice, then become owned open questions. What survives becomes a typed gap register (GAP-001 · scope | definition | number | data · blocker | minor): a blocker left open fails the gate. Prior art is checked at the problem level only — never the codebase — and owners who are absent get an exported questionnaire, not silence.

Before any plan, name the ground. Brownfield is a system you did not write: open it end to end, and check the spec against the real schemas, sources, and jobs you find. Not every fact earns an ADR — the worthiness test keeps the record honest: a decision qualifies only if it is hard to reverse, stood on downstream, and could have been otherwise. Shared vocabulary goes to docs/CONTEXT.md, the glossary later passes wire into the harness — terms only, pinned as they crystallize.

PASS 3 OF 8 · ALTITUDE: PLAN · decomposition · seam → swimlane → leg
ENGINE ·CLAUDE CODE · SAME SESSIONSKILL ·reqs-to-swimlane-plansIN · READS THE ADRS

Take the system understood in Pass 2 — same session, ADRs in hand — and cut where the system is already jointed: by feature or by component. Each seam becomes one swimlane owning its own directory under cvg/swimlanes/<seam>/; each lane holds a lean plan plus named legs — a lane's stretch with one responsibility and one proving test, each yielding 1:N task-specs at Pass 5. One lane is designated the steel thread: the narrowest end-to-end path that proves the seams compose. The right number of lanes is the number of genuine seams. No more, no fewer.

Prefer the highest seam, and the fewest — cut at the published contract, above implementation detail. And before a lane earns a plan it passes the deep-lane test: you can say what it does, how you use it, and what it depends on — without reading its internals. Two phases, one barrier — no fork, no route decision.

V7 · CONSENSUS IS THE HANDOFF · RECURSION ABSORBS SCALE · A ROUTER, NEVER A WAIVER

The method does not fork after Consensus. A different-family adversary attacks the plans, every objection is settled, the owner signs — and the hardened plan tree goes directly to Tasking. Frontier engines execute well-scoped atoms reliably, and verified atoms compose back up more safely than one monolith. The standalone six-tier Task-Spec engine carries the whole range — from a one-line change to a complete backbone — without a second specification paradigm.

HISTORICAL ROUTE — RETAINED AS ARCHAEOLOGY

The fork

wrapped the whole system in one SDD spec — one big end-to-end eval, one long human gate. Retired from the active method: a coupled slice is now an L leaf, not a separate paradigm. The consensus schema still stamps FORK: B as a compatibility value; agents treat it as required metadata, never as a prompt to choose a branch.

CURRENT METHOD — TWO PHASES, ONE BARRIER

The descent

Design (0–4) is human-led: the owner's judgment shapes intent, terrain, seams, and survives an adversary. The barrier is the owner's sign-off. Build (5–8) is machine-led: every unit carries its own eval, and no human hand-verifies what a gate can check. One spine, top to bottom.

THE SIX-TIER ENGINE ABSORBS THE RANGE

Leaves run · nodes decompose

Leaves (XS/S/M/L) are runnable atoms — each fits one fresh context window and verifies as one PR / test-suite; a gate-checked write-surface budget catches a mis-sized unit. Nodes (XL/XXL) are not runnable — they MUST declare children and expand into leaves. A worker dispatches the children, never the node.

WHY ONE PATH IS SAFER

Recursion, not escalation

Big work used to route out to a second paradigm. Now it decomposes in: the same Task-Spec format, self-similar at every scale, so the seam contracts are written once and per-unit tasks can't drift.

THE ROUTER — CVG LANE · NOT A PASS

cvg lane "add a health endpoint" → LANE=FAST|NORMAL|FULL. The router chooses how much of the descent a given goal deserves — it never waives a gate. FAST work still ends at a sealed, eval-backed task; it just skips the ceremony the goal doesn't need.

TASKS ALL THE WAY DOWN — AND BACK UP

The dark factory needs one unit model at every scale. A subjective slice becomes a human-checkpoint eval; a coupled slice becomes an L leaf; a whole backbone becomes an XXL node that decomposes to a tree of leaves. There is no route out: descend by decomposition, run only leaves, then compose verified results back up.

ENGINE ·STANDALONE taskspec 3.8CLI ·cvg tasks validate | gate | dod | acceptGATE · TIER=1

Consensus hands off here, always. The hardened plans decompose into eval-backed Task-Specs — the trust boundary wraps each unit, and verification is per-unit. Each tasks/T-*.md carries YAML frontmatter, six zones, ≥3 runnable bash evals, and an Exit Check — the definition of done travels inside the file. The engine is the deepest contract in the chain, and since v5 it lives in its own repository: Converge consumes the published CLI and its contracts, and installs no mirrored skill.

Two gates are duals. PRE — safe-to-delegate --stamp certifies the spec and HMAC-seals the evals, so the spec is the only trusted instruction source and goalposts cannot silently move. POST — accept-task --stamp certifies the work: clean-checkout eval pass, blast-radius check, HMAC recheck, and an optional gold-sanity Goodhart guard (the eval must FAIL on the unpatched baseline).

GATE — SAFE-TO-DELEGATE

Every task carries a runnable eval — no eval, not a task yet. The delegation gate runs structural + sizing validation, then a broken-eval guard, and refuses to delegate a node (a worker dispatches its children). Loop Engineering is the discipline of designing the loops that prompt agents, rather than prompting agents. Convergence is defined by the goal, never by attempt-count: a loop that stops because it tried three times has not converged; a loop that stops because the eval is green has. The loop never chooses work — it receives exactly one issue, verifies its Pass 7 execution profile, reads the signed Task-Spec plus hash-bound evidence (the only instruction source), cuts a branch, and actually loops until the task's own eval exits 0.

Settlement — green is necessary, never sufficient.

ATTEMPT-BOUND HANDOFF · INDEPENDENT ACCEPTANCE · TIER-2 REFUTATION

The executor's word settles nothing. When the loop goes green, Converge mints an attempt-bound TaskHandoff/v3 in the final workspace and asks the standalone Task-Spec engine — the authority that sealed the task — to independently accept it. TIER 1

The task's own eval

sealed at Pass 5, re-run by the acceptance gate on a clean checkout — it never trusts the executor's word, and a non-zero exit is rejected automatically.

TIER 2

A different family judges

SEPARATION

Neither manufactures the other

THE CLOSE CONDITION

Only the task's own green eval plus independent acceptance earns a PR and closes an issue. THE HONEST BOUNDARY

The Loop converges to green evals, not to correct outcomes. A passing spec test guarantees only that the code matches the spec — if the spec is wrong, the code faithfully implements the wrong thing. The Dark Factory automates the build, not the judgment of whether the spec was right. The defense is structural and partial, not total: Pass 1's gate forces the spec to answer the brief, Pass 4's adversary attacks it before any code is written, and tier-2 attacks the diff after. Stating this plainly is the point — the intellectual honesty is the moat's foundation, not a footnote.

The loop never inspects what a task is — it inspects one thing: does the task carry a runnable eval, and is that eval green. All role-specificity is pushed down into the per-task eval, which is precisely why one method serves every discipline.
