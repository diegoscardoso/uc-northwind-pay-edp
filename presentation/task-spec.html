the missing contract

A prompt describes intent.
A Task-Spec binds authority and proof.

Without a stable contract, every executor silently invents its own meaning of done.

prompt onlyInterpretation drifts
doneDefined during execution, often by the same actor doing the work.
scopeBuried in chat, with no sealed write surface or Do-Not-Touch boundary.
proofA claim such as tests passed, detached from the exact revision and attempt.
handoffEach harness receives a different summary and reconstructs missing context.
Task-Spec contractMeaning stays fixed
doneBehavior and runnable evals are declared before execution.
scopePaths, exclusions, budgets, dependencies, and backend policy are explicit.
proofReceipts bind evidence to task, revision, authorization, attempt, and base.

The unit of trust is not the conversation. It is the sealed task revision plus independently checked evidence.

PRE authorization

The seal covers the exact work.
Change the contract, lose the authority.

HMAC v3 authorizes an attempt. It never proves that the attempt succeeded.

TaskRevision/v1 · sealed envelope

task ID + body digest + authority manifest digest

signature = HMAC-SHA256(key, TaskAuthorization/v3 envelope)

TaskHandoff/v3

The handoff carries authority.
It does not carry trust by implication.

One portable envelope lets different harnesses execute the same authorized attempt.

identityTask revision

Task ID, body digest, and authority manifest digest.

authorizationTier and seal

Exact PRE verdict and the authority envelope used.

attemptUUID and base

Unique attempt identity plus the base commit it starts from.

closureRequired proof

Exit Check, eval set, and the expected closure semantics.

scopeWrite surface

Allowed paths, Do-Not-Touch paths, and blast-radius policy.

budgetsBounded attempts

Retries, time, and execution limits carried into the harness.

backendExecution policy

Backend constraints without provider credentials or private evaluator secrets.

commandsPublic surface

Runnable commands and public evidence policy. The handoff never invokes a model.

optional execution control plane

TaskMesh coordinates attempts.
Task-Spec keeps the authority.

The runtime consumes an authorized frontier. It cannot widen the contract or accept on its own terms.

Task-Spec core

Owns truth

  • Seals exact authority
  • Exposes safe ready frontier
  • Validates receipts
  • Mints acceptance
TaskMesh runtime

Owns coordination

  • Durable runs and events preserve execution history
  • Leases and fences prevent stale workers from claiming authority
  • Routing and worktrees isolate bounded attempts
  • Supervised adapters or optional autonomous OMP containers execute the handoff
still human

Owns integration

  • Review supervised decisions
  • Merge target branch
  • Push or open pull request
  • Finish prints the route only
eligible→leased→running→verifying→awaiting supervision / accepted→integrated by human
explicit nonclaims
No hosted control plane. No production reliability claim. No protocol certification. No automatic target merge.
